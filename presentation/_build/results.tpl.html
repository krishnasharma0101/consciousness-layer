1. The question

The Sandwich Model puts a graph memory (the "Consciousness Layer") between two LLM calls. Memory turns are nodes, and the edges are weighted by Wij = S·T·F·R (semantic, temporal, emotional, reinforcement). Retrieval spreads activation over the graph and follows an A* path. Testable question: does this layer retrieve the right memories, or produce better answers, than plain retrieval?

Data and protocol
  • v0 synthetic dialogues (120 probes), LongMemEval-S (470 questions), LoCoMo (10 conversations, 1,536 questions; 277 multi-hop)
  • Every experiment after v0 was pre-registered, with a numeric prediction and a falsifier written down before the run
  • Paired bootstrap 95% CIs, sign-flip tests, Holm correction
  • CPU only: MiniLM-L6 encoder, Qwen2.5-1.5B reader

2. v0 synthetic dialogues R-2026-10-20-01 · backfilled, not pre-registered

40 dialogues × 3 probe types (recall, update, contradiction), Qwen2.5-1.5B, n = 120.

Draft contamination. The full Sandwich (always refine) scored 94/120 against RAG's 113/120. Its retrieval was perfect (gold fact retrieved in 120/120 cases for every retriever), so the loss came from the prompt. Passing the Primary LLM's wrong draft to the Secondary LLM pulled it toward the wrong answer, mostly on contradiction probes (19/40 vs 34/40). With the same graph retrieval and no draft, it scored 114/120. Shuffled W scored 95, the same as real W. The λ trigger as written scored 44.

CIs are 95% Wilson intervals from results/v0/summary.csv. For "no draft" the interval is computed here from 114/120 (per_probe_nodraft.csv). The no-draft run was exploratory. This benchmark saturates retrieval, so it cannot tell retrievers apart. That is why the later runs use real benchmarks.

3. LongMemEval-S retrieval R-2026-10-26-02 · pre-registered · n = 470

Each retriever ranks every turn of a ~500-turn chat history. The metric is whether a gold evidence turn lands in the top-k.

Paired difference vs the full graph (v1)

By question type (turn_any@10)

The graph as a first-stage retriever is 3.6 points worse than plain cosine (0.819 vs 0.855; Δ −0.036 [−0.062, −0.011], Holm p 0.055). Shuffled weights are no worse, and removing S, T or E raises nDCG. Only the topology helps: random edges are clearly worse (−0.098 vs cosine).
The largest gain in any run had nothing to do with the graph. RRF(BM25, cosine) = 0.913 [0.887, 0.938], +0.057 [0.028, 0.087] over cosine. This was exploratory here, so it was re-tested in a pre-registered run on LoCoMo (section 6).

RRF on LongMemEval-S comes from R-2026-10-26-04 (first-stage rows, all 470 questions). Its CI is the one logged in LAB_NOTEBOOK.md. RRF nDCG has no logged CI, so it is shown as a point only. x_* rows are exploratory sweeps (ζ, recency).

5. Is Cnorm an error signal? R-2026-10-26-03 · pre-registered

The paper says to refine when C is low. Test: does −Cnorm predict retrieval misses (AUROC, 0.5 = chance)? Baselines: −max cosine (plain retrieval confidence), and the residual of Cnorm once max cosine is accounted for.

Weak. AUROC 0.63–0.68 on LongMemEval-S, below plain max-cosine for v1 and cosine misses (0.72, 0.74). After removing max-cosine, only 0.56–0.59 is left. Φdyn gives the same AUROC as Cnorm, because it is the trajectory mean of a converging Cnorm. The high synthetic AUROCs (0.89–0.94) rest on only 6–7 errors and a probe-type confound.

6. LoCoMo: hybrid confirmation and multi-hop graph test R-2026-11-03-02 / -03 · pre-registered

LoCoMo is a second, independent dataset: long two-person chats over 19–32 sessions. Metric: all-evidence@10, meaning every gold evidence turn is in the top 10.

(a) H1, the hybrid retrieval confirmation (N = 1,536): confirmed

RRF − cosine = +0.102 [0.081, 0.124], RRF − BM25 = +0.026 [0.007, 0.045], both with Holm p < 0.05. RRF beat cosine in 10/10 conversations. Against BM25 it won in 7/10, and the conversation-clustered CI includes 0 [−0.006, +0.063], so the BM25 comparison is the fragile one.

In (b): blue line = RRF, orange dashed line = the pre-registered +0.03 bar.

(b) H2, the graph's last fair chance: multi-hop questions (category 1, ≥ 2 evidence turns, N = 277): falsified

Pre-registered bar: the graph re-rank must beat RRF by ≥ +0.03. Primary S-only re-rank: Δ 0.000 [0, 0]. Both falsifiers fired. The most aggressive graph setting gained +0.018 [−0.004, +0.043], below the bar, and none of the 20 family tests survives Holm (smallest pHolm = 0.13). The headroom is large (RRF gets all the evidence for only 10.5% of these questions), so this is not a ceiling effect.

7. End-to-end QA with a small reader R-2026-11-03-04 · pre-registered · N = 277

Qwen2.5-1.5B-Instruct reads the 10 retrieved turns and answers LoCoMo multi-hop questions. Metric: LoCoMo partial token-F1. No LLM judge, no paid API.

Mean F1 by arm (95% CI)

Paired differences

Graph context = RRF context: −0.0006 [−0.015, +0.013] (answers differ on 12/277). The full Sandwich retrieval path is no better (−0.038, Holm 0.11). Unlike v0, the draft did not anchor the answer here (+0.009, CI spans 0). Reader quality is limited by retrieval recall: F1 is 0.565 when all evidence is in context and 0.222 when it is not.

9. The research process: pre-register → run → log

Before each run, the hypothesis, a numeric prediction and a falsifier were written into LAB_NOTEBOOK.md. Afterwards the real numbers and a prediction check were appended, each tied to a git commit. Failed predictions, a spec error, a pre-registration flaw and an aborted run are all logged rather than hidden.
